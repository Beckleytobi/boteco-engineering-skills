# Pack-level design handoff

Use design-handoff.json for the whole HLD or LLD pack even when all diagrams are justifiably omitted. This is the existing handoff contract expressed as a checked local record; it does not grant approval.

Required fields: artifact_id, artifact_version (strings), design_level (HLD/LLD), lifecycle (DRAFT/READY), freshness (CURRENT/STALE/INVALIDATED), baseline_path (local JSON within the pack), baseline {baseline_id,version,content_hash}, and traceability [{decision_id,requirement_ids,acceptance_criterion_ids}]. Map every material decision; reuse canonical requirement and decision IDs. The baseline copy is immutable evidence, not a new source of product decisions.

DRAFT permits pending approval or stale dependencies only with explicit limitations; all identities, hashes and known-ID links must still be valid. READY requires CURRENT freshness and approval evidence bound to the baseline ID, version and hash. READY means structurally ready against governing approvals; it does not claim the design itself is approved, authorize implementation or replace semantic review. Record the design's own approval separately under the shared handoff contract.

LLD also declares hld. For a dependency use state REFERENCED, path to a local immutable HLD content payload, artifact_id, artifact_version, content_hash, freshness and approval. The payload includes artifact_id, artifact_version, design_level HLD and its baseline identity; hash its entire JSON content using sorted keys, compact separators and UTF-8. Keep approval outside that payload. For READY, hld.approval requires state APPROVED, the same artifact_id/artifact_version/content_hash/baseline, authority, decided_at and evidence_reference; HLD normally governs the same requirements baseline. An older baseline in the same lineage may remain current only with requirements_used and equivalence_review: decision EQUIVALENT, exact from_baseline/to_baseline, requirements_reviewed matching the entire declared dependency set, reviewer, reviewed_at, evidence_reference and rationale. Preserve the original HLD approval bound to its original baseline. This reuses the shared handoff equivalence rule; it never renews historical approval automatically.

If HLD does not apply, hld is {state: NOT APPLICABLE, reason, scope, evidence, introduces_system_boundary: false}. A new system boundary cannot use this exemption; return that decision to System Design. Missing HLD approval can be explored in a labelled DRAFT, never represented as approved.

The design pack validator checks this handoff independently from visual completion. Valid drafts may still have incomplete visuals: report the two outcomes separately. Content truth, completeness of all decisions, evidence authenticity and actual approval authority remain review obligations. Old packs need explicit reviewed handoff/coverage additions, not invented metadata or silent reapproval.
